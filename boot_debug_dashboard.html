Identified Issues

1. Boot Disk Type Mismatch

Stage 1 bootloader uses hard disk (HD) read parameters, but QEMU boots from a floppy image. BIOS returns different sector geometry for floppies.

QEMU: -drive file=${FLOPPY_IMAGE},format=raw,if=floppy

✓ Solution:

  • Bootloader must detect drive type (floppy vs HD)
  • Use INT 13h AH=08h to get actual drive parameters
  • Or hard-code floppy parameters for floppy images

2. No Error Reporting from Stage 1

Current bootloader prints 'E' on error but doesn't show error code, making diagnosis impossible. We don't know which INT 13h error occurred.

jc floppy_error ; Carry flag set = error, but code not printed

✓ Solution:

  • Print error code in hex (AH register contains error number)
  • Print drive number being accessed
  • Print sector parameters (CHS or LBA)

3. Floppy Disk Layout Not Verified

The CMakeLists.txt creates the floppy image but doesn't verify stage2.bin is at the expected location. FAT filesystem may have different sector layout than bootloader expects.

✓ Solution:

  • Dump floppy image to verify stage2.bin placement with: mcopy -i main_floppy.img -D o :: | head -20
  • Verify boot sector is correctly written as first 512 bytes
  • Check FAT filesystem structure matches expected layout

4. Wrong CHS Parameters for Floppy

Bootloader hardcodes CHS (Cylinder/Head/Sector) addresses designed for hard disks. 1.44MB floppies have different geometry: 80 cylinders × 2 heads × 18 sectors.

mov ch, 0 ; Cylinder mov cl, 2 ; Sector mov dh, 0 ; Head

✓ Solution:

  • For LBA 2 on 1.44MB floppy: cylinder=0, head=0, sector=3 (LBA+1)
  • Or switch to INT 13h Extended Read (AH=42h) using LBA directly
  • Or auto-detect geometry with INT 13h AH=08h

5. Missing Debug Output in Stage 2

Even if Stage 1 successfully loads Stage 2, we won't know where execution stops. No output until FAT init happens.

✓ Solution:

  • Stage 2 entry should immediately print debug marker
  • Print at each major step: A20 enable, GDT load, protected mode switch
  • Print before and after FAT operations

Memory Layout

0x00000000: Interrupt Vector Table (IVT)
0x00000400: BIOS Data Area
0x00000500: → Stage 2 Load Address (target)
0x00007C00: → Stage 1 Code (this is where BIOS loads bootloader)
0x00100000: Kernel Load Address (MEMORY_LOAD_KERNEL)

Floppy Disk Structure (1.44MB)

LBA CHS Content Size Status
0 C:0 H:0 S:1 Boot Sector (Stage 1) 512 B ✗ Unverified
1 C:0 H:0 S:2 FAT #1 (first sector) 512 B ✗ Unverified
2+ C:0 H:0 S:3+ stage2.bin (should be here) ~50 sectors ✗ READ FAILED
– – FAT #2, Root Dir, kernel.bin – ? Unreachable

  • Drive number (hex)

Step 2: Verify Floppy Image

  • LBA Extended: Use INT 13h AH=42h
Step 4: Enhance Stage 2 Debug

  • GDT load
  • Protected mode switch
