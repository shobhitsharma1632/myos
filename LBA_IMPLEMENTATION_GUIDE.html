🖥️ LBA + Hard Drive Implementation Guide

Switching from floppy to hard drive with LBA + CHS fallback support

Overview of Changes

Current Setup (Floppy)

  • Boot drive: 0x00 (floppy)
  • Disk read: CHS only
  • Boot sector: Minimal
  • File location: Fixed
  • Error handling: Basic

New Setup (Hard Drive)

  • Boot drive: 0x80 (hard drive) ✓
  • Disk read: LBA + CHS fallback ✓
  • Boot sector: Full FAT12 BPB ✓
  • File location: Dynamic (reads FAT) ✓
  • Error handling: 3 retries + reset + messages ✓
✓ Why This Works: Hard drives support LBA extensions. When QEMU boots a hard drive image, it sets DL=0x80, which enables full INT 13h extended support including LBA.

Step 1: Update CMakeLists.txt (Image Creation)

What to Change

Modify how the disk image is created and how QEMU boots it.

Current Code (Floppy)

add_custom_target(run COMMAND ${QEMU_I386_EXECUTABLE} -drive file=${FLOPPY_IMAGE},format=raw,if=floppy -nographic -serial mon:stdio DEPENDS floppy_image COMMENT "Running OS in QEMU..." )

New Code (Hard Drive)

add_custom_target(run COMMAND ${QEMU_I386_EXECUTABLE} -drive file=${FLOPPY_IMAGE},format=raw,if=ide -nographic -serial mon:stdio DEPENDS floppy_image COMMENT "Running OS in QEMU..." )
⚠️ Key Change: if=floppy → if=ide
This tells QEMU to treat the image as an IDE hard drive (DL=0x80) instead of a floppy (DL=0x00).

Alternative Options

Option Drive Number (DL) Description
if=ide 0x80 Primary IDE (recommended)
if=ahci 0x80 AHCI (SATA emulation)
-hda 0x80 Shorthand for IDE primary

Step 3: Add Build System Support (stage2_location table)

What's Needed

The bootloader needs to know where stage2.bin lives on the FAT filesystem. The build system computes this and writes it to the bootloader.

In boot.asm, add:

section .data global stage2_location stage2_location: times 30 db 0 ; Table filled by build system have_extensions: db 0 ; LBA support flag

In CMakeLists.txt, add logic to:

  1. Create hard disk image with FAT filesystem
  2. Write stage2.bin to FAT
  3. Compute stage2.bin's LBA location(s)
  4. Write LBA addresses to bootloader's stage2_location table
  5. Write bootloader to disk sector 0
⚠️ Complex Part: Computing LBA locations from FAT filesystem layout requires understanding FAT12 structure. nanobyte_os uses a custom tool or script for this.

Simpler Alternative: For now, use fixed offsets (like current approach) but read from FAT at boot. This sacrifices flexibility but is simpler.

Step 4: Key Code Snippets

FAT12 BIOS Parameter Block (to add at start)

section .fsjump jmp short start nop section .fsheaders bdb_oem: db "MYOS8ACK" bdb_bytes_per_sector: dw 512 bdb_sectors_per_cluster: db 1 bdb_reserved_sectors: dw 1 bdb_fat_count: db 2 bdb_dir_entries_count: dw 0xE0 bdb_total_sectors: dw 2880 bdb_media_descriptor_type: db 0xF0 bdb_sectors_per_fat: dw 9 bdb_sectors_per_track: dw 18 bdb_heads: dw 2 bdb_hidden_sectors: dd 0 bdb_large_sector_count: dd 0 ebr_drive_number: db 0 db 0 ebr_signature: db 0x29 ebr_volume_id: dd 0x12345678 ebr_volume_label: db "MYOS " ebr_system_id: db "FAT12 "

LBA Support Detection (to add in main code)

mov ah, 0x41 ; Check Extensions mov bx, 0x55AA stc int 13h jc .no_disk_extensions cmp bx, 0xAA55 jne .no_disk_extensions mov byte [have_extensions], 1 .no_disk_extensions:

Disk Read with LBA/CHS and Retry

disk_read: ; Parameters: EAX=LBA, CL=sectors, DL=drive ; Returns: CF=0 on success mov di, 3 ; Retry count .retry: cmp byte [have_extensions], 1 jne .chs_read ; LBA read (AH=0x42) mov [dap.lba], eax mov ah, 0x42 mov si, dap jmp .do_read .chs_read: ; CHS read (AH=0x02) call lba_to_chs mov ah, 0x02 .do_read: pusha stc int 13h jnc .success popa call disk_reset dec di jnz .retry ret .success: popa clc ret
